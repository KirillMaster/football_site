# Quickstart: проверка редактора новостей

## Предпосылки

- Учётная запись администратора сайта.
- Подготовленные файлы: одно изображение для обложки, три изображения для галереи, один ролик MP4
  (каждый ≤20 МБ), плюс один файл >20 МБ и один файл неподдерживаемого типа для проверки отказов.
- Локальный запуск: `docker compose up -d` (frontend + api + postgres); прод-проверка — через админку
  сайта.

## Автоматические проверки

```bash
# Frontend unit: сериализация/парсинг нод содержимого, формирование slug
cd src/frontend && npm run test

# Backend: команда создания новости с обложкой, загрузка медиа новостей
dotnet test src/backend
```

Ожидаемо: зелёные тесты round-trip для `content_serialization` (см. `contracts.yaml`), приём
`coverImage` в `create_news`, отсутствие прироста записей публичной фотогалереи при
`news_media_upload`.

## Сценарий 1 — новость уровня эталона (US1 + US2 + US3)

1. Войти в админку → раздел «Новости и события» → «Добавить».
2. Заполнить заголовок — убедиться, что адрес новости предложен автоматически (`AS-8`).
3. Загрузить обложку → появляется превью (`AS-1`).
4. В тексте: абзац с выделением, затем вставить галерею, выбрав **три файла за одну операцию**
   (`AS-4`); задать описание каждому изображению (`AS-5`).
5. Вставить видео → в тексте появляется плеер (`AS-6`).
6. Добавить два тега, заполнить SEO-заголовок и SEO-описание, включить публикацию.
7. Сохранить → открыть публичную страницу новости.

**Ожидается**: обложка сверху, абзацы с выделениями, три фотографии в сетке, работающий видеоплеер,
теги — состав элементов не отличается от новости, опубликованной ранее программно (`SC-001`).

## Сценарий 2 — редактирование без потерь (US1, US3, EC-7)

1. Открыть созданную новость на редактирование: галерея и видео видны в редакторе (`AS-7`).
2. Изменить только один абзац текста и сохранить.
3. Открыть публичную страницу.

**Ожидается**: обложка, теги, статус публикации, галерея и видео на месте (`AS-2`, `AS-11`, `SC-003`).

4. Повторить пункты 1-3 для новости, созданной программно (`FR-020`).

## Сценарий 3 — черновик и адрес (US3)

1. Создать новость с выключенной публикацией → в публичном списке её нет (`AS-10`).
2. Ввести адрес с недопустимыми символами → сохранение блокируется с сообщением (`AS-9`).
3. Ввести адрес существующей новости → сохранение отклонено сообщением о занятом адресе (`EC-4`).

## Сценарий 4 — чистота фотогалереи (US4)

1. Запомнить число снимков в публичной фотогалерее.
2. Загрузить три фотографии в текст новости.
3. Обновить публичную фотогалерею — число снимков не изменилось (`AS-12`, `SC-004`).
4. Загрузить фотографию через раздел фотогалереи — она появляется в публичной галерее (`AS-13`).

## Сценарий 5 — отказы загрузки (EC-1, EC-2, EC-3)

1. Выбрать одной операцией три корректных файла и один файл >20 МБ → загружены три, по четвёртому
   показано сообщение о размере (`AC-9`).
2. Выбрать документ вместо изображения → сообщение о допустимых типах.
3. Прервать сеть во время загрузки → сообщение об ошибке, набранный текст новости сохранён
   в редакторе, повтор загрузки возможен (`SC-005`).
